# Field notes

What using the skill has shown. Newest first. A note here is the reason for a change to `SKILL.md`, or a reason not
to make one.

## 2026-11-25 - day one

- Born from a day with three side quests in one session: a research page that became a public website feature, a
  video and two forum posts, and a research question about depth from one camera. None was planned; all were worth
  doing. The ask: handle these on purpose, "almost like a Git branch ... in development".
- The three were logged after the fact. That works, but the bookmark of the main quest had to be rebuilt from the
  conversation. Rule kept in the skill: open the note at the START.
- The first quest graduated within hours, straight onto the project's normal branch, because the user asked for it
  to go live. So "its own branch" cannot be absolute: a change the user wants published now goes in as its own
  commit and is recorded as graduated.
- The skill was born because it was, in and of itself, a side quest: nobody set out to write it, it branched off
  the day's work like the three before it. Writing it, and then making it its own repo, went into the ledger as a
  quest and graduated. Nested and meta quests get their own line like any other.
- Open question: when the ledger is long, does one global INDEX.md still read well, or does it need a view per
  project? Wait for real use before changing it.
